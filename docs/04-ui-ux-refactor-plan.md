# UI/UX 重构实施计划

文档状态：已完成；2026-09-14 已在 macOS aarch64 完成生产构建、Rust 工作区测试与真实浏览器验收。
关联文档：[实现方案](01-implementation-plan.md)、[实现细则](02-implementation-spec.md)。

## 1. 目标

界面应把“选择作品、判断下一步、完成一次可追溯操作”变成一条连续路径。写作者打开应用时先看到作品库；进入作品后只看到当前阶段需要的协作内容；阅读整稿、管理设置和查看任务不再与正文编辑争夺同一页面。

本轮以以下结果作为完成标准：

- 默认入口是作品库，卡片能说明当前稿本、阶段、主线进度、字数和最近更新时间。
- 工作台在桌面上提供章节目录、主画布和可调整高度的协作 Dock；窄屏目录与稿本管理改用 Sheet。
- 所有状态变化由一条可恢复的事件流驱动查询缓存更新，不在每个面板各自建立 SSE 连接。
- 未提交的目标、准备产物、章节指导、细纲、正文和审核/反馈文本保存在浏览器 IndexedDB，按本地数据目录、稿本、阶段和目标隔离；成功提交后删除对应草稿。
- 引用可以单独构成反馈；页面不得以“必须填写文字”为由禁用引用型提交。
- 全局功能有固定入口，工作台只保留与当前稿本有关的控制。

## 2. 信息架构

| 区域 | 用途 | 主入口 |
| --- | --- | --- |
| 作品库 | 继续创作、新建作品、查看作品进度 | `/works` |
| 工作台 | 当前稿本的写作、审核、阅读和章节目录 | `/works/:projectId/versions/:versionId` |
| 任务概览 | 全部可操作 Run、用量和创作进度 | `/dashboard` |
| 知识库 | Space、知识条目和索引状态 | `/knowledge` |
| 提示词模板 | 用户模板和内建提示词覆盖入口 | `/templates` |
| 系统设置 | 本地模型、服务与项目设置入口 | `/settings` |
| 回收站 | 恢复或清理可回收对象 | `/recycle` |

顶层路由使用 Hash URL，应用被本地静态服务器启动时不依赖服务器端重写规则。`/` 和未知路径都回到作品库。全局侧栏只出现在管理页面；工作台使用独立的章节目录，避免双侧栏同时占用写作空间。

## 3. 关键页面

### 3.1 作品库

卡片的标题直接链接到当前稿本，主操作根据阶段显示“继续创作”或“阅读作品”。卡片只呈现四项可比较数据：主线通过数、当前字数、番外数和当前稿本。删除走二次确认并移入回收站。

空库不是空白页：显示新建作品入口和最少解释。新建对话框只要求项目名称与作品标题，稿本标签保留默认值“初稿”。

### 3.2 工作台

工作台的头部保留返回作品库、标题、执行状态、写作/阅读切换、目录与稿本管理。阅读模式隐藏写作管理控制，避免阅读时出现无关按钮。

写作模式采用三层布局：

```text
章节目录 | 主画布（阶段说明、生成预览）
         | ─── 可拖动分隔线 ───
         | 协作 Dock（当前阶段的唯一操作面板）
```

Dock 按工作流阶段替换内容：准备、章节指导、细纲、正文和终稿审核分别使用已有的领域面板。它不是聊天记录，也不复制整篇正文；正文的长篇阅读留在阅读模式，并继续使用现有虚拟化阅读器。

### 3.3 任务概览与管理页

Dashboard 将顶层 Run 与审核子 Run 统一为任务列表，任务说明其类别、阶段和所属作品，并直接返回对应工作台。知识库、模板、设置和回收站使用同一应用框架，各自保留现有领域面板，减少无关的布局重写。

## 4. 视觉与交互规则

- 使用暖白背景、深绿主色和低对比边框；深色主题使用同一组语义 token，不在组件中硬编码主题颜色。
- 作品名和长文本容器必须允许截断或滚动；数值用本地化格式化。
- 所有破坏性操作必须有对话框确认；所有图标按钮有可访问名称；管理页和工作台都提供跳到主内容的键盘链接。
- 表单控件有显式标签、名称、可见焦点和请求中的禁用状态。错误使用 `Alert` 宣布，不用静默颜色变化传达失败。
- 每个阶段的主要推进操作由当前 Dock 决定。引用型意见可以在没有文字时提交；退回时要求文字或至少一条引用。
- 编辑中的远端快照发生变化时，保留本地文本并明确提示用户在提交前核对，而不是静默覆盖。

## 5. 数据与同步

React Query 负责读取缓存和命令后的失效；`EventSyncProvider` 每个标签页只打开一条 EventSource。连接前先读取 `/api/events/cursor`，随后以该水位建立 `/api/events?after=…`。创建项目、创建或复制稿本、切换选中稿本都会写入 `project.changed`，使作品库和任务概览能立即失效并刷新。持久事件只失效相关查询键，临时 `preview.delta` 只保留在内存，不能被误认作已保存正文。

作品库进度由 `GET /api/projects` 一次返回。后端批量读取当前稿本的章节状态与正文当前修订字数，避免每张作品卡片触发额外请求。`GET /api/dashboard` 的任务字段统一包含顶层和子 Run，前端不再专门猜测“审核任务”。

浏览器草稿的键由 `dataDir + versionId + phase + targetId` 组成。`baseRevision` 只记录草稿依赖的服务端快照，用来识别远端变更，不能参与键本身。切换章节或路由前会立即写入最后一份待提交文本；成功命令才清除它。

### 6.1 2026-09-14 macOS aarch64 验收记录

验收使用隔离的临时数据目录和本地生产静态资源。`pnpm build`（`tsc -b && vite build`）通过，路由拆分后入口 JavaScript 为 245.84 KB（gzip 79.24 KB），工作台页按需加载为 190.67 KB（gzip 55.25 KB）。`cargo fmt --all -- --check`、`git diff --check` 与 `cargo test --config 'env.PROTOC.value="/opt/homebrew/bin/protoc"' --workspace` 通过；后者共 216 个测试（agent 43、app 55、core 38、store 76、xtask 4）。

真实浏览器覆盖空数据目录、新建作品、作品库到工作台的路由加载、1440px 桌面与 390px 窄屏布局、目录 Sheet、草稿刷新恢复、成功保存后的 IndexedDB 清除、创建项目后的 SSE 跨页刷新，以及 Tab/Skip link 路径。最终复核还确认入口返回 `Cache-Control: no-cache`，Skip link 按 Enter 后 URL 仍停在 Dashboard、焦点落到 `main-content`，管理页只有一个 `main` landmark；桌面和移动工作台均只有一个目标编辑框。仅引用的退回规则由 Store 与 API 合同测试覆盖；本轮 UI 验收没有为此单独启动外部模型工作流。验收数据和本地服务在结束前清理，不保留到用户数据目录。
